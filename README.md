# TreeStore и таблица AG Grid

Тестовое задание MStroy Frontend. В репозитории есть класс `TreeStore` на TypeScript и одноэкранное приложение на Vue 3. Класс хранит плоский массив элементов как дерево и отдаёт детей, потомков и путь к корню без повторного обхода всего массива. Приложение загружает данные из JSON и показывает их в таблице AG Grid Enterprise.

## Требования

Нужен Node.js 24. Версия в `.nvmrc` равна `24`. Зависимости ставятся из `package-lock.json`.

## Установка и запуск

Установить зависимости:

```bash
npm install
```

Запустить приложение в режиме разработки:

```bash
npm run dev
```

Собрать production-сборку:

```bash
npm run build
```

Просмотреть собранное приложение:

```bash
npm run preview
```

Запустить тесты:

```bash
npm test
```

Проверить форматирование:

```bash
npm run format:check
```

## Как устроен проект

`src/store/TreeStore.ts` не зависит от Vue. Его можно импортировать в автотестах отдельно от экрана. Конструктор принимает массив элементов. У каждого элемента есть `id` типа `string | number`, `parent` типа `string | number | null` и произвольные поля. Число `1` и строка `'1'` считаются разными ключами.

Внутри класса две карты:

- `Map` по `id` хранит сами элементы в порядке загрузки.
- `Map` по `parent` хранит `Set` id детей. `Set` сохраняет порядок добавления и даёт добавление и удаление за амортизированное O(1).

Полный проход по массиву выполняется только в конструкторе и в `setItems`. Остальные методы ходят по указателям.

Публичные методы:

| Метод                | Поведение                                                              |
| -------------------- | ---------------------------------------------------------------------- |
| `getAll()`           | Возвращает все элементы в порядке загрузки.                            |
| `getItem(id)`        | Возвращает элемент по id.                                              |
| `getChildren(id)`    | Возвращает прямых детей или пустой массив.                             |
| `getAllChildren(id)` | Возвращает всех потомков без самого элемента. Обход итеративный.       |
| `getAllParents(id)`  | Возвращает цепочку от элемента до корня включительно.                  |
| `setItems(items)`    | Полностью заменяет данные.                                             |
| `addItem(item)`      | Добавляет элемент и обновляет указатели.                               |
| `removeItem(id)`     | Удаляет элемент и всех потомков.                                       |
| `updateItem(item)`   | Заменяет элемент. При смене `parent` переносит его к другому родителю. |

Приложение создаёт хранилище как `new TreeStore([])`. Файл `public/items.json` не импортируется в сборку. После монтирования экрана приложение ждёт 2 секунды, загружает файл через `fetch('/items.json')` и передаёт массив в `setItems`. Пока ответ не получен, на экране спиннер. После ответа таблица обновляется без перезагрузки страницы.

Таблица лежит в `src/components/TreeTable.vue`. Включены `treeData` и `treeDataDisplayType: 'custom'`. Путь узла собирается из `getAllParents` в обратном порядке. Колонки:

- «№ п/п» показывает номер видимой строки, начиная с 1.
- «Категория» показывает «Группа», если у элемента есть дети, иначе «Элемент». У группы есть шеврон.
- «Наименование» берёт значение поля `label`.

## Тесты

Unit-тесты `TreeStore` лежат в `tests/store`. Они проверяют все публичные методы, порядок загрузки, смешанные числовые и строковые id и удаление поддерева.

Тесты производительности запускают методы на массиве из 100 000 элементов, переносят 10 000 детей у широкого родителя и обходят дерево глубиной 25 000 уровней.

Компонентные тесты лежат в `tests/components`. Они проверяют индикатор загрузки, запрос `/items.json` после паузы в 2 секунды, три колонки таблицы и путь дерева.

## AG Grid Enterprise

Пакет `ag-grid-enterprise` в задании разрешён для ознакомления. Лицензионный ключ не задаётся, поэтому в таблице виден водяной знак пробной версии. Модули `ClientSideRowModelModule` и `TreeDataModule` регистрируются в `src/main.ts`.
